# 进京了么后端接口文档

本文档依据当前 `backend/src/main/java/cn/jinjing/app` 中的控制器、异常处理和安全配置整理。接口基地址以本机开发环境为例：`http://127.0.0.1:8080`。除健康检查外，业务接口统一使用 `/api/v1` 前缀，JSON 请求与响应使用 UTF-8。

## 鉴权与通用约定

- 本机 `APP_AUTH_ENABLED=false` 时，所有接口无需登录。启用鉴权后，查询接口和地图配置接口公开；`/api/v1/admin/**` 使用 HTTP Basic，账号来自 `APP_ADMIN_USER`，密码来自 `APP_ADMIN_PASSWORD`，用户需具有 `ADMIN` 角色。没有单独的登录接口。
- `name` 是探头名称的不区分大小写的包含匹配；`type` 是原始类型编码 `type_code_raw` 的精确匹配；`cameraType` 是统一探头类型的精确匹配。省略参数表示不按该字段筛选。
- 统一探头类型：`DISCARD`＝已废弃，`SIX_RING_OUT`＝六环外，`TWO_RING_IN`＝二环内，`SIX_RING_IN`＝六环内。服务端根据名称自动计算该字段，新增或编辑时不单独提交。
- 列表类接口返回 JSON 数组，不附带总数；需要总数时调用 `/api/v1/cameras/count`。`offset` 从 0 开始，负数按 0 处理；`limit` 会限制在接口注明的范围内。
- 探头 `id` 是统一表主键，不等同于来源 JSON 中的 `id`。写接口使用 `version` 做并发控制：先查询详情，提交其中的 `version`，冲突时重新读取。
- 下文的示例 ID、坐标、名称和密码均为占位示例，不代表数据库中的实际记录。

## 公开查询接口

### GET `/api/v1/cameras`

查询未删除的探头，按统一探头 `id` 降序排列。

| 查询参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | 字符串 | 不筛选 | 名称包含匹配 |
| `type` | 字符串 | 不筛选 | 原始类型编码精确匹配，例如来源的 `aa` |
| `cameraType` | 字符串 | 不筛选 | 统一探头类型英文枚举值 |
| `offset` | 整数 | `0` | 起始偏移，最小为 0 |
| `limit` | 整数 | `100` | 每页条数，实际限制为 1～500 |

响应 `200`，数组元素字段为 `id`、`name`、`longitude`、`latitude`、`coordinate_system`、`type_code_raw`、`camera_type`、`manual_protected`、`version`。此接口直接返回数据库列名，因此使用下划线命名。

```bash
curl 'http://127.0.0.1:8080/api/v1/cameras?name=顺义区&cameraType=SIX_RING_OUT&offset=0&limit=20'
```

### GET `/api/v1/cameras/count`

查询未删除探头的总数。支持与列表接口相同的 `name`、`type`、`cameraType` 筛选参数。响应 `200`：

```json
{"total":7322}
```

数字仅表示响应结构，实际值以数据库为准。

### GET `/api/v1/cameras/map`

只查询可视范围内、坐标系已标记为 `GCJ02` 且未删除的点位，按 `id` 升序排列。

| 查询参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `west`、`south`、`east`、`north` | 十进制数 | 必填 | 地图范围；必须满足 `west <= east`、`south <= north` |
| `name` | 字符串 | 不筛选 | 名称包含匹配 |
| `cameraType` | 字符串 | 不筛选 | 统一探头类型精确匹配 |
| `limit` | 整数 | `5000` | 最多返回 1～10000 条；超出上限时 `truncated=true` |

响应 `200` 包含 `items` 数组和布尔值 `truncated`。每个点位包含 `id`、`name`、`longitude`、`latitude`、`type_code_raw`、`camera_type`。范围顺序错误时返回 `400`。

```bash
curl 'http://127.0.0.1:8080/api/v1/cameras/map?west=116.2&south=39.8&east=116.8&north=40.3&limit=100'
```

### GET `/api/v1/cameras/{id}`

查询一条未删除探头。响应 `200` 使用驼峰命名：

```json
{
  "id": 1,
  "name": "顺义区某路口 南向北【六环外】",
  "longitude": 116.4,
  "latitude": 40.1,
  "coordinateSystem": "GCJ02",
  "typeCodeRaw": "a",
  "cameraType": "SIX_RING_OUT",
  "manualProtected": false,
  "version": 0
}
```

不存在或已删除时返回 `404`。`coordinateSystem` 为 `UNKNOWN` 的探头不会通过地图点位接口返回。详情接口当前不返回创建、更新时间。

### GET `/api/v1/cameras/{id}/comments`

查询未删除探头的评论，按可解析的评论时间降序、评论 `id` 降序排列；无法解析的时间排在最后。`offset` 默认 `0`，`limit` 默认 `100`、限制为 1～500。响应 `200` 为数组，元素字段：`id`、`nickname`、`content`、`raw_time`、`parsed_time`；`parsed_time` 可能为 `null`。探头不存在或已删除时返回空数组。

### POST `/api/v1/cameras/{id}/comments`

在未删除的探头下发表评论，`Content-Type: application/json`。昵称和内容都必填，去除首尾空白后不能是空字符串；昵称最多 30 字符，内容最多 1000 字符。启用管理认证后，此接口仍允许网站访客使用。

```json
{"nickname":"路过的司机","content":"今天经过时看到探头仍在使用。"}
```

成功返回 `201`，字段为 `id`、`nickname`、`content`、`raw_time`。评论保存在 `camera_comment`，`origin=USER`；同时向 `camera_audit_log` 写入操作者为 `user` 的新增评论记录，管理员可在定时抓取页的“操作留痕”查看。探头不存在或已删除返回 `404`，输入无效返回 `400`。后续数据源导入只追加评论，不会覆盖这条网站评论。

### GET `/api/v1/cameras/{id}/images`

查询未删除探头的图片，按图片 `id` 升序排列。响应 `200` 为数组，元素字段：`id`、`url`。探头不存在或已删除时返回空数组。来源 JSON 若包含 `images` URL 数组，导入时按 URL 去重；当前躲猫猫导出尚未提供图片，因此此接口可能返回 `[]`。

### GET `/api/v1/site/map-config`

响应 `200`，返回前端初始化高德地图所需的配置：

```json
{"key":"<高德 Web Key>","securityJsCode":"<高德安全密钥>","coordinateSystem":"GCJ02"}
```

未配置时字符串为空或坐标系为 `UNKNOWN`。此接口当前公开，响应会包含实际配置值；文档和示例中不要填写真实密钥。

## 管理接口

### POST `/api/v1/admin/cameras`

人工新增探头，请求头为 `Content-Type: application/json`。请求体：

```json
{
  "name": "顺义区某路口 南向北【六环外】",
  "longitude": 116.4,
  "latitude": 40.1,
  "typeCodeRaw": ""
}
```

`name` 必填且非空白；`longitude` 必填且范围为 -180～180；`latitude` 必填且范围为 -90～90；`typeCodeRaw` 必须提供、不能为 `null`，可用空字符串表示没有原始编码。响应 `201`：`{"id":<新探头 ID>}`。新增记录默认启用 `manualProtected`，坐标系默认是 `UNKNOWN`，不会立即出现在地图点位接口中。

### PATCH `/api/v1/admin/cameras/{id}`

人工编辑探头。尽管使用 `PATCH`，当前实现要求完整提交 `name`、`longitude`、`latitude`、`typeCodeRaw`，并提供从详情接口取得的 `version`：

```json
{
  "name": "顺义区某路口 南向北【六环外】",
  "longitude": 116.4,
  "latitude": 40.1,
  "typeCodeRaw": "",
  "version": 0
}
```

响应 `200` 为更新后的详情，`version` 增加 1，且启用人工保护。记录不存在或已删除返回 `404`；版本不一致返回 `409`；缺少 `version` 返回 `400`。服务端按更新后的名称重新计算 `cameraType`，不接受单独修改该枚举值。

### DELETE `/api/v1/admin/cameras/{id}?version={version}`

按版本软删除探头。`version` 查询参数必填；成功响应 `200`、无响应体。删除后公开查询不再返回该探头；版本不一致或记录不存在返回 `409`。来源后续同步不会自动恢复人工删除的记录。

### POST `/api/v1/admin/cameras/{id}/restore`

恢复一条已软删除的探头。成功响应 `200`、无响应体，`version` 增加 1 并启用人工保护；未找到已删除记录返回 `404`。此接口当前不要求提交 `version`。

### POST `/api/v1/admin/imports`

使用 `multipart/form-data` 上传一个文件字段 `file`，导入来源固定为 `duomaomao`。上传文件不能空，文件大小上限为 50 MB。文件根节点必须是 JSON 对象，包含 `cameras` 数组与等于数组长度的整数 `total`；每条记录必须有唯一且非空的来源 `id`。`generatedAt` 如提供，需是可解析的带时区时间。

响应 `202`，导入在后台执行：

```json
{"batchId":12,"status":"QUEUED"}
```

上传阶段的结构错误通常返回 `400`。单条记录的名称、`aa`、坐标、评论等错误会记录到该批次的逐条结果中，不会回滚整批。相同来源 ID 的再次导入会更新已关联探头，不会创建重复探头。

```bash
curl -F 'file=@../duomaomao-cameras.json' 'http://127.0.0.1:8080/api/v1/admin/imports'
```

启用鉴权时，在管理员请求中加 `-u '管理员账号:管理员密码'`，不要把真实密码写入脚本或仓库。

### GET `/api/v1/admin/imports/{id}`

查询导入批次。响应 `200` 字段：`id`、`status`、`total`、`inserted`、`updated`、`unchanged`、`failed`、`detailWarnings`、`startedAt`、`finishedAt`、`error`。时间和 `error` 在未完成或无错误时可为 `null`。批次不存在返回 `404`。

批次状态：`QUEUED`（排队）、`RUNNING`（运行中）、`SUCCEEDED`（全部成功）、`PARTIAL_SUCCESS`（部分记录失败）、`FAILED`（批次执行失败或启动时发现上次中断）。`detailWarnings` 表示来源记录包含 `detailError` 的数量，此类记录不会导入评论。

### GET `/api/v1/admin/imports/{id}/records`

查询某批次的逐条处理结果，按文件中的 `row_number` 升序排列。

| 查询参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `offset` | 整数 | `0` | 起始偏移，最小为 0 |
| `limit` | 整数 | `100` | 每页条数，实际限制为 1～500 |
| `status` | 字符串 | 不筛选 | 精确匹配 `INSERTED`、`UPDATED`、`UNCHANGED` 或 `FAILED` |

响应 `200` 为数组，元素字段：`row_number`、`source_record_id`、`camera_id`、`status`、`error_message`、`review_note`。`review_note` 表示同名远距等需人工核对的情况。不存在的批次也返回空数组，而不是 `404`。

```bash
curl 'http://127.0.0.1:8080/api/v1/admin/imports/12/records?status=FAILED&offset=0&limit=100'
```

## 定时抓取与操作留痕

`/sync.html` 是管理员任务页面。启用鉴权后，该页面和以下接口都需要 HTTP Basic 管理员身份；本机关闭鉴权时可直接访问。自动任务由 `APP_SYNC_ENABLED` 控制，默认关闭，启用后北京时间每日 03:00 执行。手动触发不受自动开关影响，但需要已配置躲猫猫令牌。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/admin/sync/config` | 凭据与调度状态、下次执行时间、归档目录 |
| POST | `/api/v1/admin/sync/runs` | 立即创建任务，响应 `202`：`{"runId":1,"status":"QUEUED"}`；已有活动任务返回 `409` |
| GET | `/api/v1/admin/sync/runs?offset=0&limit=20` | 历史任务，按 ID 倒序 |
| GET | `/api/v1/admin/sync/runs/{id}` | 当前阶段、抓取和导入进度、统计、错误、归档路径 |
| GET | `/api/v1/admin/sync/runs/{id}/records?status=FAILED&reviewOnly=false` | 逐条导入结果、待核对说明 |
| GET | `/api/v1/admin/sync/runs/{id}/records/{sourceId}` | 该批次来源探头的完整原始 JSON |
| GET | `/api/v1/admin/sync/runs/{id}/events` | 任务阶段与错误事件 |
| GET | `/api/v1/admin/sync/runs/{id}/audit` | 该次任务造成的实际变更及前后值 |
| GET | `/api/v1/admin/sync/audit?cameraId=123` | 全部操作留痕，含人工维护；`cameraId` 可选 |
| GET | `/api/v1/admin/sync/runs/{id}/file` | 下载该次任务的原始 JSON |

列表接口支持 `offset`、`limit`，`limit` 限制在 1～500。导入记录另支持 `status` 和 `reviewOnly`。任务状态为 `QUEUED`、`FETCHING`、`ARCHIVING`、`IMPORTING`、`SUCCEEDED`、`PARTIAL_SUCCESS`、`FAILED`、`INTERRUPTED`；前端显示中文。抓取产生详情错误时，文件仍保存、有效记录仍导入，原有评论不清空，任务显示“部分完成”。同日重跑替换日期归档，但各批次按 SHA-256 保存的不可变副本继续可下载。

## 健康检查与错误响应

`GET /actuator/health` 公开，健康时通常返回 `200` 和 `{"status":"UP"}`；不健康时状态码及附加字段由 Spring Boot Actuator 决定。

业务异常通常使用 `{"error":"错误说明"}`：资源不存在为 `404`，版本冲突为 `409`，参数或请求体校验失败为 `400`。启用鉴权后，管理员接口未提供有效 HTTP Basic 凭据通常返回 `401`；权限不足返回 `403`。超过上传大小限制、JSON 解析错误及其他未被业务异常处理器捕获的异常，按 Spring Boot 默认错误响应处理，格式不保证为上述 `error` 对象。

页面入口 `/`、`/index.html`、`/admin.html` 和 `/sync.html` 属于静态页面，不是 JSON API。
