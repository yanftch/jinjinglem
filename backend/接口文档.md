# 进京了后端接口文档

本文档依据当前 `backend/src/main/java/cn/jinjing/app` 中的控制器、异常处理和安全配置整理。接口基地址以本机开发环境为例：`http://127.0.0.1:8080`。除健康检查外，业务接口统一使用 `/api/v1` 前缀，JSON 请求与响应使用 UTF-8。

## 鉴权与通用约定

- 本机 `APP_AUTH_ENABLED=false` 时，管理员接口无需登录；会员接口与两条路线规划接口仍独立校验对应客户端的会话和权益。启用鉴权后，查询接口和地图配置接口公开；`/api/v1/admin/**` 只接受已登录管理员的会话 Cookie。后台只有 `APP_ADMIN_USER` 对应的一个管理员账号，当前用户名为 `adsmaxa`；密码来自 `APP_ADMIN_PASSWORD`。浏览器访问 `/login.html` 登录，成功后进入 `/manage.html`；`POST /logout` 退出。管理写操作需要 CSRF 令牌：登录后请求 `GET /api/v1/admin/csrf`，保留会话 Cookie 及响应的 `XSRF-TOKEN` Cookie，并在 POST、PATCH、DELETE 请求头中发送响应 JSON 的 `token` 值作为 `X-XSRF-TOKEN`。浏览器管理页自动处理。登录表单的 CSRF 令牌可从公开的 `GET /api/v1/auth/csrf` 获取。
- `name` 是探头名称的不区分大小写的包含匹配；`type` 是原始类型编码 `type_code_raw` 的精确匹配；`cameraType` 是统一探头类型的精确匹配。省略参数表示不按该字段筛选。
- 生产接口使用 HTTPS。公开接口按客户端 IP 限流：管理员登录每 15 分钟最多 10 次，微信登录和 Android 注册分别每 15 分钟最多 20 次，用户上报每小时最多 10 次，路线规划每分钟最多 12 次，其他路线接口每分钟最多 120 次，其他公开 API 每分钟最多 300 次。超限返回 HTTP `429`、中文错误 JSON 和 `Retry-After` 秒数。限流计数保存在当前应用进程内，应用重启会重置；目前 VPS 为单实例部署。
- 统一探头类型：`DISCARD`＝已废弃，`SIX_RING_OUT`＝六环外，`TWO_RING_IN`＝二环内，`SIX_RING_IN`＝六环内。新增探头未指定 `cameraType` 时按名称判定；人工编辑和用户上报审核可显式指定该枚举值。
- 列表类接口返回 JSON 数组，不附带总数；需要总数时调用 `/api/v1/cameras/count`。`offset` 从 0 开始，负数按 0 处理；`limit` 会限制在接口注明的范围内。
- 探头 `id` 是统一表主键，不等同于来源 JSON 中的 `id`。写接口使用 `version` 做并发控制：先查询详情，提交其中的 `version`，冲突时重新读取。
- 下文的示例 ID、坐标、名称和密码均为占位示例，不代表数据库中的实际记录。

## 公开查询接口

### GET `/api/v1/cameras`

查询未删除的探头，按统一探头 `id` 降序排列。

| 查询参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | 字符串 | 不筛选 | 名称包含匹配 |
| `type` | 字符串 | 不筛选 | 原始类型编码精确匹配，例如来源的 `aa` |
| `cameraType` | 字符串 | 不筛选 | 统一探头类型英文枚举值 |
| `offset` | 整数 | `0` | 起始偏移，最小为 0 |
| `limit` | 整数 | `100` | 每页条数，实际限制为 1～500 |

响应 `200`，数组元素字段为 `id`、`name`、`longitude`、`latitude`、`coordinate_system`、`type_code_raw`、`camera_type`、`manual_protected`、`version`。此接口直接返回数据库列名，因此使用下划线命名。

```bash
curl 'http://127.0.0.1:8080/api/v1/cameras?name=顺义区&cameraType=SIX_RING_OUT&offset=0&limit=20'
```

### GET `/api/v1/cameras/recent`

查询最近 7×24 小时内写入统一探头表的未删除记录，按 `created_at`、`id` 降序排列，最多返回 5 条。响应 `200`，数组字段为 `id`、`name`、`camera_type`、`created_at`；没有记录时返回空数组。人工新增、审核用户上报、采集结果经管理员审核后入库的探头都按其**实际入库时间**计算。仅抓取或归档、尚未审核入库的记录不会出现在公开接口；已有探头的再次抓取或更新也不算新增。

### 小程序模式与到达记录

`GET /api/v1/site/miniprogram-mode` 返回 `{ "mode": "LIVE" }` 或 `{ "mode": "REVIEW" }`。默认 `LIVE`。小程序每次进入前台时读取模式：实际模式加载探头与冷启动新增弹窗；提审模式进入独立的行程足迹页，展示地图、到达记录按钮和本人最近 20 条地点记录，不请求探头列表。模式接口失败时小程序暂不展示探头数据。网页与 Android 不受该配置影响。

管理员在 `POST /api/v1/admin/miniprogram-mode` 发送 `{ "mode": "REVIEW" }` 或 `{ "mode": "LIVE" }`，切换与审计同一事务写入 `miniprogram_mode`、`miniprogram_mode_audit`。可在 `/manage.html?page=miniprogram-mode` 查询当前配置、切换历史和到达记录。

提审模式的到达记录由 `POST /api/v1/review/arrivals` 写入，要求小程序登录会话 Bearer，无需 VIP；请求 JSON 包含 GCJ-02 `longitude`、`latitude` 和可选 `accuracy`（米，0～5000）。响应 `201`，字段为 `id`、`longitude`、`latitude`、`accuracy_m`、`coordinate_system`、`created_at`。非提审模式返回 `409`。`GET /api/v1/review/arrivals` 只返回当前小程序账号最近 20 条。管理员可使用 `GET /api/v1/admin/review-arrivals?page=0&size=20` 分页查看全部记录，响应包含 `total` 和 `items`。

### GET `/api/v1/cameras/count`

查询未删除探头的总数。支持与列表接口相同的 `name`、`type`、`cameraType` 筛选参数。响应 `200`：

```json
{"total":7322}
```

数字仅表示响应结构，实际值以数据库为准。

### GET `/api/v1/cameras/map`

只查询可视范围内、坐标系已标记为 `GCJ02` 且未删除的点位，按 `id` 升序排列。

| 查询参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `west`、`south`、`east`、`north` | 十进制数 | 必填 | 地图范围；必须满足 `west <= east`、`south <= north` |
| `name` | 字符串 | 不筛选 | 名称包含匹配 |
| `cameraType` | 字符串 | 不筛选 | 统一探头类型精确匹配 |
| `limit` | 整数 | `5000` | 最多返回 1～10000 条；超出上限时 `truncated=true` |

响应 `200` 包含 `items` 数组和布尔值 `truncated`。每个点位包含 `id`、`name`、`longitude`、`latitude`、`type_code_raw`、`camera_type`。范围顺序错误时返回 `400`。

```bash
curl 'http://127.0.0.1:8080/api/v1/cameras/map?west=116.2&south=39.8&east=116.8&north=40.3&limit=100'
```

### GET `/api/v1/cameras/map/search`

`name` 必填。去除首尾空格后，按探头名称做不区分大小写的包含匹配；空白关键词返回空数组。返回所有未删除、坐标系为 `GCJ02` 的匹配点位，不受当前地图范围限制，也不分页。每个点位包含 `id`、`name`、`longitude`、`latitude`、`camera_type`。首页搜索使用这些坐标计算范围并自动调整地图中心和缩放。

```bash
curl 'http://127.0.0.1:8080/api/v1/cameras/map/search?name=香堤北街'
```

### GET `/api/v1/cameras/{id}`

查询一条未删除探头。响应 `200` 使用驼峰命名：

```json
{
  "id": 1,
  "name": "顺义区某路口 南向北【六环外】",
  "longitude": 116.4,
  "latitude": 40.1,
  "coordinateSystem": "GCJ02",
  "typeCodeRaw": "a",
  "cameraType": "SIX_RING_OUT",
  "manualProtected": false,
  "version": 0
}
```

不存在或已删除时返回 `404`。`coordinateSystem` 为 `UNKNOWN` 的探头不会通过地图点位接口返回。详情接口当前不返回创建、更新时间。

### GET `/api/v1/cameras/{id}/comments`

查询未删除探头的评论，按可解析的评论时间降序、评论 `id` 降序排列；无法解析的时间排在最后。`offset` 默认 `0`，`limit` 默认 `100`、限制为 1～500。响应 `200` 为数组，元素字段：`id`、`nickname`、`content`、`raw_time`、`parsed_time`；`parsed_time` 可能为 `null`。探头不存在或已删除时返回空数组。

### POST `/api/v1/cameras/{id}/comments`

在未删除的探头下发表评论，`Content-Type: application/json`。昵称和内容都必填，去除首尾空白后不能是空字符串；昵称最多 30 字符，内容最多 1000 字符。启用管理认证后，此接口仍允许网站访客使用。

```json
{"nickname":"路过的司机","content":"今天经过时看到探头仍在使用。"}
```

成功返回 `201`，字段为 `id`、`nickname`、`content`、`raw_time`。评论保存在 `camera_comment`，`origin=USER`；同时向 `camera_audit_log` 写入操作者为 `user` 的新增评论记录，管理员可在定时抓取页的“操作留痕”查看。探头不存在或已删除返回 `404`，输入无效返回 `400`。后续数据源导入只追加评论，不会覆盖这条网站评论。

### GET `/api/v1/cameras/{id}/images`

查询未删除探头的图片，按图片 `id` 升序排列。响应 `200` 为数组，元素字段：`id`、`url`。探头不存在或已删除时返回空数组。来源 JSON 若包含 `images` URL 数组，导入时按 URL 去重；当前躲猫猫导出尚未提供图片，因此此接口可能返回 `[]`。

### GET `/api/v1/site/map-config`

响应 `200`，返回前端初始化高德地图所需的配置：

```json
{"key":"<高德 Web Key>","securityJsCode":"<高德安全密钥>","coordinateSystem":"GCJ02"}
```

未配置时字符串为空或坐标系为 `UNKNOWN`。此接口当前公开，响应会包含实际配置值；文档和示例中不要填写真实密钥。

## 路线规划接口

路线规划复用 `duomaomao-spring` 的 `DuomaomaoService`，由 backend 对小程序和 Android 提供统一地址。路线接口不需要管理员 Cookie 和 CSRF，但必须提供 `Authorization: Bearer <会员会话>`；小程序需有有效试用或会员，Android 设备账号需有管理员开通的有效会员。地图查询仍免费。上游采集凭据沿用 `DUOMAOMAO_BEARER_TOKEN` 或 `DUOMAOMAO_BEARER_TOKEN_FILE`；未配置时调用返回 `503`，不影响 backend 启动。上游规划会消耗额度，服务层最多同时处理 3 个请求，繁忙时返回 `429`。

### POST `/api/v1/routes/plan`

请求体中的坐标为 GCJ-02 十进制度。`licence`：1 无任何证件、2 六环外进京证、3 六环内进京证；`preference`：1 速度最快、2 距离最短、3 不走高速。两者省略时默认 1。`waypoints` 最多 6 个；客户端传入的 `openid` 会被忽略。服务端生成任务标识并绑定当前会员，防止跨账号查询。

```json
{
  "licence": 3,
  "preference": 1,
  "startPoint": {"name": "起点", "address": "起点", "latitude": 39.865, "longitude": 116.378},
  "endPoint": {"name": "终点", "address": "终点", "latitude": 40.075, "longitude": 116.610},
  "waypoints": []
}
```

成功返回 `200`：`isSuccessOnPlanRoute`、`routePlanResponse`、`navigationSteps`、`distance`、`useTime` 等字段。`routePlanResponse` 始终为二维数组，每个子数组是一段的 `{longitude,latitude}` 点位。`isSuccessOnPlanRoute=false` 表示当前证件条件不可行，仍可能返回完整线路；这时顶层 `distance`/`useTime` 不代表实际路程。上游报告 `FUNCTION_TIME_LIMIT_EXCEEDED` 时返回 `202 {"status":"PENDING","requestId":"r_..."}`，小程序随后轮询结果。

### GET `/api/v1/routes/result?openid=r_...`

仅可查询当前会员的任务结果，Android 与小程序的任务归属分别校验；任务标识来自 `202` 响应。响应 `200` 为 `{"isSuccess":true,"result":{...}}`；未完成时为 `{"isSuccess":false}`。小程序每 5 秒轮询一次，最多等待 3 分钟。其他上游错误返回 `502`，不向客户端透出上游原始响应体。

### POST `/api/v1/routes/amap/plan`

Java 后端调用高德 Web 服务驾车路径规划 2.0，并使用统一探头表校验路线。请求坐标为 GCJ-02；只接受 `preference`（1 速度优先、2 在高德候选中选较短路线、3 不走高速）、`startPoint`、`endPoint` 和最多 6 个 `waypoints`。高德路线不判断进京证条件，因此**不接收 `licence` 作为可行性判断依据**。示例：

```json
{
  "preference": 1,
  "startPoint": {"name": "起点", "latitude": 39.865, "longitude": 116.378},
  "endPoint": {"name": "终点", "latitude": 40.075, "longitude": 116.610},
  "waypoints": []
}
```

成功返回 `200`，包含 `provider="AMAP"`、`avoidsKnownCameras=true`、`cameraRadiusMeters=100`、`routePlanResponse`（二维折线点位）、`navigationSteps`、`distance` 和 `useTime`。只校验未删除、非废弃、GCJ-02 的已收录探头；半径默认 100 米，可由 `APP_ROUTE_CAMERA_RADIUS_METERS` 调整。无法找到符合该避让条件的路线时返回 `422`、`code=NO_CAMERA_FREE_ROUTE`；未配置或无权限的 Web 服务 Key 返回 `503`、`code=AMAP_NOT_CONFIGURED`；本机繁忙或高德配额/频率超限返回 `429`，高德上游异常返回 `502`。错误响应均包含中文 `error`，不包含 Key。

此接口所需的 `AMAP_WEB_SERVICE_KEY` 与网页地图的 `AMAP_JS_KEY` 是不同类型的 Key；未配置 Web 服务 Key 不影响应用启动或原有躲猫猫路线接口。探头避让仅基于现有数据库点位，不能保证覆盖现场所有探头。

## 管理接口

### POST `/api/v1/admin/cameras`

人工新增探头，请求头为 `Content-Type: application/json`。请求体：

```json
{
  "name": "顺义区某路口 南向北【六环外】",
  "longitude": 116.4,
  "latitude": 40.1,
  "typeCodeRaw": ""
}
```

`name` 必填且非空白；`longitude` 必填且范围为 -180～180；`latitude` 必填且范围为 -90～90；`typeCodeRaw` 必须提供、不能为 `null`，可用空字符串表示没有原始编码。`cameraType` 可选；省略时按名称自动分类。响应 `201`：`{"id":<新探头 ID>}`。新增记录默认启用 `manualProtected`，坐标系默认是 `UNKNOWN`，不会立即出现在地图点位接口中。

### PATCH `/api/v1/admin/cameras/{id}`

人工编辑探头。尽管使用 `PATCH`，当前实现要求完整提交 `name`、`longitude`、`latitude`、`typeCodeRaw`，并提供从详情接口取得的 `version`：

```json
{
  "name": "顺义区某路口 南向北【六环外】",
  "longitude": 116.4,
  "latitude": 40.1,
  "typeCodeRaw": "",
  "cameraType": "SIX_RING_OUT",
  "version": 0
}
```

响应 `200` 为更新后的详情，`version` 增加 1，且启用人工保护。`cameraType` 可选；提供时按所选枚举值保存，省略时保留原有类型，即使名称发生变化也不会重新分类。无效枚举值返回 `400`；记录不存在或已删除返回 `404`；版本不一致返回 `409`；缺少 `version` 返回 `400`。管理页编辑弹窗会回显并提交现有类型，管理员可单独修改。

### DELETE `/api/v1/admin/cameras/{id}?version={version}`

按版本软删除探头。`version` 查询参数必填；成功响应 `200`、无响应体。删除后公开查询不再返回该探头；版本不一致或记录不存在返回 `409`。来源后续同步不会自动恢复人工删除的记录。

### POST `/api/v1/admin/cameras/{id}/restore`

恢复一条已软删除的探头。成功响应 `200`、无响应体，`version` 增加 1 并启用人工保护；未找到已删除记录返回 `404`。此接口当前不要求提交 `version`。

### POST `/api/v1/admin/imports`

使用 `multipart/form-data` 上传一个文件字段 `file`，导入来源固定为 `duomaomao`。上传文件不能空，文件大小上限为 50 MB。文件根节点必须是 JSON 对象，包含 `cameras` 数组与等于数组长度的整数 `total`；每条记录必须有唯一且非空的来源 `id`。`generatedAt` 如提供，需是可解析的带时区时间。

响应 `202`，导入在后台执行：

```json
{"batchId":12,"status":"QUEUED"}
```

上传阶段的结构错误通常返回 `400`。单条记录的名称、`aa`、坐标、评论等错误会记录到该批次的逐条结果中，不会回滚整批。相同来源 ID 的再次导入会更新已关联探头，不会创建重复探头。

```bash
curl -F 'file=@../duomaomao-cameras.json' 'http://127.0.0.1:8080/api/v1/admin/imports'
```

启用鉴权时，脚本需要先通过登录表单建立会话并保留 Cookie，再提交管理请求。管理写操作还需从 `/api/v1/admin/csrf` 获取令牌；不要把真实密码写入脚本或仓库。

### GET `/api/v1/admin/imports/{id}`

查询导入批次。响应 `200` 字段：`id`、`status`、`total`、`inserted`、`updated`、`unchanged`、`failed`、`detailWarnings`、`startedAt`、`finishedAt`、`error`。时间和 `error` 在未完成或无错误时可为 `null`。批次不存在返回 `404`。

批次状态：`QUEUED`（排队）、`RUNNING`（运行中）、`SUCCEEDED`（全部成功）、`PARTIAL_SUCCESS`（部分记录失败）、`FAILED`（批次执行失败或启动时发现上次中断）。`detailWarnings` 表示来源记录包含 `detailError` 的数量，此类记录不会导入评论。

### GET `/api/v1/admin/imports/{id}/records`

查询某批次的逐条处理结果，按文件中的 `row_number` 升序排列。定时/手动抓取任务在审核通过前没有入库结果；此时请查询下文的 `/reviews` 预览接口。直接上传 JSON 的管理员导入接口仍会立即入库。

| 查询参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `offset` | 整数 | `0` | 起始偏移，最小为 0 |
| `limit` | 整数 | `100` | 每页条数，实际限制为 1～500 |
| `status` | 字符串 | 不筛选 | 精确匹配 `INSERTED`、`UPDATED`、`UNCHANGED`、`REJECTED` 或 `FAILED` |

响应 `200` 为数组，元素字段：`row_number`、`source_record_id`、`camera_id`、`status`、`error_message`、`review_note`。`review_note` 表示同名远距等需人工核对的情况。不存在的批次也返回空数组，而不是 `404`。

```bash
curl 'http://127.0.0.1:8080/api/v1/admin/imports/12/records?status=FAILED&offset=0&limit=100'
```

## 定时抓取与操作留痕

`/manage.html` 是统一管理后台，左侧可切换 `/admin.html` 探头管理、`/sync.html` 任务与留痕、`/review.html` 逐条审核、`/reports.html` 用户上报审核。启用鉴权后，这些页面、各自的 CSS/JS 和以下接口都需要管理员会话；首页 `/` 及地图查询继续公开，本机关闭鉴权时可直接访问。自动任务由 `APP_SYNC_ENABLED` 控制，默认关闭，启用后北京时间每日 03:00 执行。手动触发不受自动开关影响，但需要已配置躲猫猫令牌。两种抓取方式都只归档并生成预览，必须经管理员审核后才更新统一探头数据库。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/admin/sync/config` | 凭据与调度状态、下次执行时间、归档目录 |
| POST | `/api/v1/admin/sync/runs` | 立即创建任务，响应 `202`：`{"runId":1,"status":"QUEUED"}`；已有活动任务返回 `409` |
| GET | `/api/v1/admin/sync/runs?offset=0&limit=20` | 历史任务，按 ID 倒序 |

| GET | `/api/v1/admin/sync/runs/{id}/reviews?prediction=NEW&decision=PENDING&offset=0&limit=100` | 分页查看逐条预览；两个筛选参数均可省略 |

## 用户上报与人工审核

小程序“我的 → 用户反馈”提交 `POST /api/v1/camera-reports`，字段为 `nickname`（1～30 字）、`content`（1～2000 字）、`screenshot`（选填，最大 1 MB，仅 PNG/JPEG/WebP）。有截图时使用 `multipart/form-data`，无截图时也可使用 `application/x-www-form-urlencoded` 提交昵称和内容。响应 `201`：`{"id":23,"status":"PENDING"}`。上报记录及可选截图保存在 PostgreSQL 的 `camera_report` 表，**不会直接生成探头**；审核前截图仅管理员可查看。

管理员访问 `/reports.html`，左侧可输入道路名或路口名称搜索北京候选地址。选中候选后地图按地址匹配精度调整中心和缩放，但不会把粗定位结果当作最终坐标；再点击地图、拖动候选标记或使用地图中心选点，GCJ-02 经纬度才会回填到表单。页面用二环、六环边界推荐类型，边界附近提示人工复核；管理员可手动修改。右侧核对昵称、说明、截图和上报时间。管理接口如下：

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/admin/camera-reports?status=PENDING&offset=0&limit=30` | 分页列表；状态可为 `PENDING`、`APPROVED`、`REJECTED`，省略为全部；每页最多 100 条 |
| GET | `/api/v1/admin/camera-reports/{id}` | 详情，含 `hasScreenshot` 与 `screenshotBytes`，不包含截图二进制 |
| GET | `/api/v1/admin/camera-reports/{id}/screenshot` | 有截图时返回原始图片字节；无截图返回 `404` |
| POST | `/api/v1/admin/camera-reports/{id}/approve` | 审核通过并创建探头；JSON 示例见下文 |
| POST | `/api/v1/admin/camera-reports/{id}/reject` | 驳回；JSON 为 `{"reason":"位置无法核实"}`，原因必填、最多 500 字 |

通过请求体：

```json
{"name":"顺义区某路口 南向北【六环外】","longitude":116.1234567,"latitude":40.1234567,"cameraType":"SIX_RING_OUT","typeCodeRaw":"","coordinateConfirmed":true,"publishScreenshot":false}
```

审核通过会在同一事务中新建人工保护的 `camera` 记录，自动计算 `name_match`，坐标系固定为 `GCJ02`。提供 `cameraType` 时按该枚举值入库；旧客户端省略时仍按名称推断。通过 `camera_report.camera_id` 保留与原始上报的关联，并写入 `CREATE_FROM_REPORT` 审计记录。`publishScreenshot` 可省略，默认 `false`：截图只作为管理员审核材料；有截图且选择 `true` 后才会同步写入 `camera_image`，公开图片由 `GET /api/v1/cameras/{id}/reported-image` 返回；无截图时选择 `true` 返回 `400`。审核选择保存在 `camera_report.publish_screenshot` 和审计记录中。附近 100 米内同名探头会返回 `409`，需先核对。驳回只更新上报状态与原因。已处理的上报再次审核返回 `409`；原始记录和审核结果仍保留。

## 新增用户评论日报

管理员访问 `/daily-comments.html`（或 `/manage.html?page=comments`）查看列表，默认筛选近 7 天（含今天，北京时间）。`GET /api/v1/admin/comments/daily/summary/range` 需要 `startDate=yyyy-MM-dd`、`endDate=yyyy-MM-dd`，返回 `startDate`、`endDate`、`count`；列表接口传相同日期参数及 `offset`、`limit`（1～500，默认 50）进行区间分页。开始日期不得晚于结束日期。日期区间按北京时间解释，包含结束日全天，筛选 `origin=USER` 的评论，并返回 `id`、`camera_id`、`camera_name`、`nickname`、`content`、`comment_time`。为兼容日报管理，`GET /api/v1/admin/comments/daily/summary?date=yyyy-MM-dd` 和列表 `?date=yyyy-MM-dd` 仍保留按单日查询；单日摘要返回 `date`、`count`、`mailStatus`、`mailError`、`sentAt`。邮件每天北京时间 03:00 发送，统计区间保持不变；发送状态及失败原因保存在 `daily_comment_report`。`POST /api/v1/admin/comments/daily/retry?date=yyyy-MM-dd` 只会重试失败且已结束的日期，已经发送过的日期不会重复发信。VPS 默认发往 `qiuyanfeng678@163.com`；邮件凭据和调度开关见根目录 README。

用户探头上报日报按 `camera_report.created_at` 统计北京时间昨日内的新提交，不限当前审核状态，计数及详情与邮件共用查询结果。每天 03:00 发送，主题包含日期和上报数量，正文列出编号、提交时间、昵称、状态及内容；零上报也发送摘要。VPS 由 `APP_CAMERA_REPORT_MAIL_ENABLED=true` 启用，收件地址由 `APP_CAMERA_REPORT_MAIL_TO` 配置；发送状态记录在 `daily_camera_report_mail`，应用重启会补发未完成的昨日日报，成功日期不会重复发送。

## 健康检查与错误响应

`GET /actuator/health` 公开，健康时通常返回 `200` 和 `{"status":"UP"}`；不健康时状态码及附加字段由 Spring Boot Actuator 决定。

业务异常通常使用 `{"error":"错误说明"}`：资源不存在为 `404`，版本冲突为 `409`，参数或请求体校验失败为 `400`。启用鉴权后，管理员接口未登录返回 `401`；已登录但权限不足或 CSRF 校验失败返回 `403`。超过上传大小限制、JSON 解析错误及其他未被业务异常处理器捕获的异常，按 Spring Boot 默认错误响应处理，格式不保证为上述 `error` 对象。

页面入口 `/`、`/login.html`、`/manage.html` 及各管理单页属于静态页面，不是 JSON API。启用鉴权后，`/` 和 `/login.html` 可匿名打开；其他管理页面和资源需登录，未登录访问会跳转登录页；直接访问 `/index.html` 也需要管理员身份。

## 会员与支付接口

Android 客户端使用下文独立的设备账号，不使用本节的微信动态码或小程序购买接口。两种客户端都可调用路线规划接口，但各自的 Bearer 会话和会员有效期分别校验。

小程序启动时调用 `wx.login`，以 `POST /api/v1/members/wechat-login` 的 `{"code":"微信临时码"}` 换取 `token` 和 `member`。后续会员及路线请求使用 `Authorization: Bearer <token>`；会话有效 30 天。**新 OpenID 首次创建账号时，服务端原子发放一条 `WELCOME` 来源的 30 天会员权益**，重复登录不会续期。该账号的两天试用同时标记为已使用，避免赠送结束后再领取试用；已有账号不补发赠送，仍可通过 `POST /api/v1/members/trial` 首次启动原有两天试用，重复调用不会重置。未登录返回 `401 MEMBER_LOGIN_REQUIRED`，权益过期返回 `403 MEMBERSHIP_REQUIRED`。

`GET /api/v1/members/me` 返回 `member`（数据库顺序 `id`、对外展示的 8 位随机 `memberNo`、`active`、`trialStarted`、`trialExpiresAt`、`welcomeExpiresAt`、`vipExpiresAt`、`expiresAt`）、`purchaseAvailable` 及最近 50 笔 `orders`。`memberNo` 使用大写字母和数字（排除易混淆字符），在数据库唯一约束保证唯一；用户联系管理员时提供此编号。`POST /api/v1/members/orders` 传 `{"plan":"MONTH|YEAR","code":"新获取的 wx.login code"}`；后端再次核对 OpenID，返回 `orderNo`、金额（分）及 `payParams`，小程序将参数原样传给 `wx.requestVirtualPayment`。月卡 1000 分 / 30 天，年卡 10800 分 / 365 天，叠加到当前到期时间。缺支付配置时返回 `503 MEMBER_UNAVAILABLE`，首登赠送及已有会员仍有效。客户端支付成功回调只提示“正在核实”，不发权益。

`POST /api/v1/members/app-code` 仅接受小程序会话，返回 `code` 和 `expiresInSeconds=600`；每次生成会废止此前未使用的码。`POST /api/v1/members/app-login` 是原有一次性动态码换会话接口，现有 Android 客户端不调用它；它也不会与 Android 设备账号合并。

自建消息推送地址为 `/api/v1/members/payment-notify`，微信后台需配置 **JSON 安全模式**、Token、EncodingAESKey 并订阅虚拟支付消息。后端验证消息签名和 AppID；已验证的发货推送核对 OpenID、商品、数量及本地订单后幂等开通，退款推送需再查微信订单状态确认才回收权益。未收到推送时每 5 分钟补查待支付订单，并定期复查已支付订单。`member_payment_event` 仅存事件摘要及处理结果，不保存密钥。退款须先由微信确认；部分退款与 iOS 退款问询需要真机联调确认后再开放生产支付。

## Android 设备会员接口

Android 首次启动、且用户同意设备数据用途后，客户端在本机用包名、`ANDROID_ID` 与安装随机盐生成 SHA-256 `deviceId`，另生成 256 位随机 `deviceSecret`。原始 Android ID 不上传。调用 `POST /api/v1/android/users/register`，JSON 请求体例如 `{"deviceId":"64位小写十六进制","deviceSecret":"64位小写十六进制","manufacturer":"Xiaomi","brand":"Redmi","model":"K70","deviceName":"vermeer","androidVersion":"15","sdkInt":35,"appVersion":"1.0.0"}`。设备信息字段可选，原始 Android ID 不上传。首次登记写入独立的 `android_user` 表，并在响应中返回 `newUser=true`；重复登记核对同一设备凭据、更新设备资料并返回 `newUser=false`，不会新增第二个用户；凭据不一致返回 `401`。响应还包含 `token` 和 `user`，令牌仅返回一次，服务端只存其哈希，会话有效 30 天。客户端使用 `Authorization: Bearer <token>` 调用 `GET /api/v1/android/users/me`，响应 `user` 含设备资料、`active`、`memberExpiresAt`、`createdAt` 和 `lastSeenAt`；此查询会更新最近使用时间；未开通时到期时间为空字符串。会话过期可用本机保存的设备标识及凭据重新登记。客户端无需注册、登录或小程序动态码。

Android 路线规划前先查询 `/api/v1/android/users/me`，后端在每次调用 `/api/v1/routes/plan`、`/api/v1/routes/amap/plan` 和 `/api/v1/routes/result` 时再次校验 `android_user.member_expires_at > now()`；无会员返回 `403 MEMBERSHIP_REQUIRED`。异步结果的任务归属保存在 `android_route_request`，不与小程序账号混用。Android 没有自动赠送和购买功能。卸载重装或清除应用数据会生成新的安装随机盐和设备账号，已有权益不会自动迁移。

管理员在 `/manage.html?page=android-users` 查询设备用户，`GET /api/v1/admin/android-users?page=0&size=20&query=` 按用户编号、设备标识、厂商、品牌或型号筛选；响应包含 `summary`（累计用户、北京时间今日新增、有效 VIP）和 `items`（含设备资料）；`GET /api/v1/admin/android-users/{id}` 返回详情。`POST /api/v1/admin/android-users/{id}/membership` 请求 `{"plan":"MONTH","reason":"人工开通原因"}`，`plan` 可为 `MONTH`（从操作时起 30 天）、`YEAR`（365 天）、`CUSTOM`（指定到期时间）、`NONE`（取消）；自定义示例 `{"plan":"CUSTOM","expiresAt":"2027-01-01T00:00:00Z","reason":"人工设置"}`，时间须在未来 10 年内；每次设置覆盖原到期时间，原因必填且不超过 500 字。成功变更与 `android_user_admin_audit` 审计写入同一事务，失败尝试另记 `FAILED`；审计不保存设备凭据或会话令牌。`GET /api/v1/admin/android-users/history?page=0&size=20&userId=&outcome=&from=&to=` 可按用户、结果和 ISO-8601 时间范围查询，页面为 `/manage.html?page=android-user-history`。管理接口需管理员会话，写操作需 CSRF。上述页面和接口需部署本版后才在 VPS 生效。

### 客服微信二维码

管理员在 `/manage.html?page=android-users` 底部上传微信二维码。`POST /api/v1/admin/contact/wechat-qr` 使用 `multipart/form-data` 的 `file` 字段，接受实际内容为 PNG 或 JPEG、最大 2MB、最大边长 4096 像素的图片；需要管理员会话及 CSRF。图片保存在 `contact_qr` 单行表中，后续上传会替换旧图。`GET /api/v1/contact/wechat-qr` 公开返回图片字节及正确的 `Content-Type`；未上传时返回 `404`。当前 Android 客服页改用安装包内置的 `品牌设计/微信二维码.jpg`，不再请求此接口；该接口保留供其他客户端或后续在线更换使用。二维码中不写入后台账号信息，付款后由管理员核对用户提供的设备标识，再手动设置会员有效期。数据库迁移分别为 V16（二维码）和 V17（设备资料），已部署至 VPS。

## 会员管理员接口

小程序微信会员管理与下文的 Android 设备会员管理使用不同的数据表和后台入口。

`GET /api/v1/admin/members?page=0&size=20&query=` 按数据库顺序编号、8 位会员编号或 OpenID 搜索，列表同时返回 `id`（顺序编号）和 `member_no`（唯一会员编号）；`GET /api/v1/admin/members/orders?page=0&size=20&memberId=&orderNo=` 查订单；`GET /api/v1/admin/members/{id}` 查详情，`member` 同样包含 `id` 与 `memberNo`。每页最多 100 条。Flyway V19 为既有会员一次性生成会员编号，新建会员由后端生成并在数据库唯一约束冲突时重试。

`POST /api/v1/admin/members/{id}/change` 请求体例如 `{"action":"GRANT","days":30,"reason":"人工补发原因","orderId":123}`（`orderId` 可选）；调整到期用 `SET_EXPIRY` + ISO-8601 `expiresAt`，撤销人工权益用 `REVOKE` + `entitlementId`。原因必填。成功变更和 `member_admin_audit` 写入同一事务；被拒绝或执行失败的操作另记 `FAILED`。审计表仅追加，保留操作人、来源 IP、请求标识、结果与变更前后快照，不存令牌与密钥。`GET /api/v1/admin/members/history?page=0&size=20&memberId=&memberNo=&orderId=&action=&outcome=&from=&to=` 支持按顺序编号或会员编号筛选，列表返回 `member_id` 与 `member_no`，时间使用 ISO-8601，按时间倒序。页面入口为 `/manage.html?page=members` 和 `/manage.html?page=member-history`。
